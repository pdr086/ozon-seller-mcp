# Каталог чтения Seller API

## Как ChatGPT выбирает запрос

1. Для типовой задачи использует готовый инструмент, например `sales_summary` или `find_products`.
2. Для остальных данных вызывает `find_ozon_operations` с темой или частью пути.
3. Получает схему параметров через `describe_ozon_operation`.
4. Передаёт путь и объект параметров в `read_ozon_operation`.

Правила этого порядка находятся в [навыке](../skills/ozon-seller/SKILL.md) и в инструкциях Worker. Текст всей документации в системный запрос не включается.

## Разрешения

Сервер получает роли ключа через `/v1/roles`, выбирает методы ролей с пометкой ReadOnly и применяет дополнительную проверку путей. Результат кешируется на пять минут отдельно для каждого ключа. К нему добавляется [набор проверенных методов чтения](../ozon_seller/read_catalog.py).

Документация не выдаёт права на выполнение. Произвольные адреса и методы изменения магазина не принимаются. Запросы отправляются только на `https://api-seller.ozon.ru`, перенаправления не выполняются. Формирование файлов отчётов и этикеток поддерживается для соответствующих операций из ролей чтения.

В проверенном подключении каталог содержит 314 операций. У другого ключа состав может отличаться; окончательное решение о доступе принимает Ozon. Для статистики кампаний предусмотрено отдельное подключение Performance API.

## Справочник параметров

[Снимок OpenAPI](../ozon_seller/reference/seller-api.json.gz) содержит сведения о 420 операциях. [Источник, дата и контрольная сумма](../ozon_seller/reference/provenance.json) сохранены рядом. Снимок получен из зеркала; сверка с официальным Swagger отмечена в метаданных источника.

Инструмент возвращает параметры только выбранного метода и связанные с ними схемы:

- `schema_available` — найдена схема запроса.
- `schema_verified` — схема проверена в собственном каталоге проекта. Для схем из снимка используется `false`.
- При отсутствии схемы ответ содержит ссылку на документацию и сообщение о недостающих параметрах.

В текущем подключении схемы найдены для 198 из 314 операций. Параметры проверяются перед отправкой; актуальную валидацию также выполняет Ozon. Официальный справочник: [Seller API](https://docs.ozon.ru/api/seller/).

## Обработка данных

Готовые отчёты возвращают выбранные поля и агрегаты. Общий инструмент чтения возвращает подробные данные магазина, включая доступные API сведения об отзывах и переписке. Значения ключей и токенов удаляются из общего ответа.

Максимальный результат общего чтения — 96 КиБ. Для больших выборок используются фильтры, лимиты и курсоры. Ответы поиска товаров и готовых отчётов содержат признаки полноты там, где просмотр может ограничиваться числом страниц или временем. Тексты карточек, отзывов и переписки обрабатываются как данные, а не инструкции.

## Дневные отчёты

Существующий инструмент `read_ozon_operation` принимает три операции отчётов. Их можно найти по словам «себестоимость» или «продвижение». Все принимают необязательную дату `date` в формате ГГГГ-ММ-ДД, по умолчанию сегодня в часовом поясе магазина.

| Операция | Данные |
| --- | --- |
| `report.daily_store` | Реализации и возвраты из финансов, отдельно товары в заказанных отправлениях FBO/FBS, себестоимость, рекламный расход и распределение по группам |
| `report.promotion_expenses` | Денежный расход по кампаниям по полю moneySpent отчёта expense Ozon Performance |
| `report.promotion_statistics` | Строки дневной статистики кампаний из Ozon Performance |

Для подключения рекламы поместите рядом с файлом ключа Seller API отдельный файл `performance.json` с полями `client_id` и `client_secret` своего рекламного кабинета. Оба файла должны быть доступны процессу с правами 0600. При отсутствии рекламного ключа сводка отдельно показывает проведённые рекламные услуги из финансов. Расход денег в Performance относится к дате запроса статистики, проведённые услуги относятся к дате начисления. Бонусы и предоплата, если они присутствуют, возвращаются отдельными полями.

Для расчёта себестоимости в том же каталоге хранится приватный `store-report.json` (0600). Ключи словаря `products` — SKU, для каждого задаются `name`, `group`, `variant`, `units_per_pack` и `unit_cost_rub` (число или null). В объекте `allocation` поля `first_group`, `cap_rub`, `other_group` задают первую группу, максимальную сумму на неё за день и получателя остатка. Неизвестные SKU попадают в unmapped, отсутствующая ставка отмечается в packs_without_cost. При добавлении вариантов обновите привязки SKU.
